1. CHAR_INFO — 4 байта

	Char — 2 байта (union: Unicode 2 б / ASCII 1 б)
	Attributes — 2 байта (битовая маска: 4 бита текст + 4 бита фон + служебные флаги вроде 0x0100)

2. Двойная буферизация

	Рисуем в скрытый буфер, затем атомарно переключаем его на экран. Пользователь никогда не видит промежуточные состояния (очистку/недорисовку) → мерцания нет.

3. Один WriteConsoleOutputW vs много вызовов

	Меньше syscall'ов → меньше переключений user↔kernel и работы планировщика ОС.

	Один непрерывный блок памяти (80×25×4 = 8000 б) → эффективная загрузка в кэш процессора (пространственная локальность), меньше обращений к DRAM.
Кэш-память процессора

	Один вызов: весь массив CHAR_INFO (8000 б) лежит непрерывно → процессор грузит его в кэш блоками (cache lines) 
	за счёт пространственной локальности → мало обращений к DRAM.

	Много вызовов: данные «размазаны» → частые промахи кэша (cache misses) → дорогие походы в память.

Планировщик ОС

	Каждый syscall = переключение user ↔ kernel (сохранение контекста, проверки, работа планировщика).

	Один WriteConsoleOutputW = одно переключение вместо тысяч → служебные затраты ОС минимальны.
