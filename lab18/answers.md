. Почему в Linux нет WriteConsoleOutputW

В Windows консоль — объект ядра с буфером экрана, 
нужен спец-API (WriteConsoleOutputW) для записи матрицы CHAR_INFO. 
В Linux программа просто пишет байты в stdout, а эмулятор терминала сам их разбирает и рисует. 
Ядро буфер экрана не хранит — специальный API не нужен, хватает sys_write.
2. Как эмулятор обрабатывает поток

Работает как конечный автомат: обычные байты → печатает символы; 
0x1B (ESC) → вход в разбор ANSI-последовательности; 
читает параметры ([, цифры, ;) и финальный символ (H, m, J) → выполняет действие (курсор, цвет, очистка). 
Весь графический API — внутри эмулятора, не в ядре.
3. Если забыть reset_color (ESC[0m)

Эмулятор хранит состояние (state): цвет текста/фона, позицию, режимы — и они сохраняются между командами. Без сброса последний цвет (например, красный на чёрном) останется активным: приглашение shell, вывод всех программ и командная строка будут рисоваться этим цветом, пока пользователь не выполнит reset или не закроет терминал. Поэтому сброс обязателен.
4. Сколько байт занимает «20» в 0x1B, "[5;20H"

Два байта: 0x32 ('2') и 0x30 ('0') — ASCII-коды символов, не один байт 0x14 (=20).

    ANSI — текстовый протокол: числа передаются символами ("20" = 2 байта), эмулятор парсит их сам.

    Бинарная передача: число как значение в машинном формате (1 байт 0x14).
